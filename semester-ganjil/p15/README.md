# Pertemuan 15 - Testing & Bug Fixing + User Acceptance Test

## 🏭 Konteks Industri
Sebuah aplikasi yang canggih tidak ada gunanya jika sering **crash** atau menghasilkan data yang salah. Di industri, kualitas sebuah software diukur dari seberapa sedikit bug yang ditemukan oleh pengguna akhir. Proses **Quality Assurance (QA)** dan **Testing** adalah tahap krusial sebelum produk dirilis ke pasar.

**User Acceptance Test (UAT)** adalah momen "pembuktian" di mana klien mencoba aplikasi secara langsung. Jika aplikasi lolos UAT, berarti kontrak selesai dan pembayaran bisa dicairkan. Developer profesional harus bisa mendokumentasikan bug, memperbaikinya secara sistematis, dan memastikan fitur yang sudah berjalan tidak rusak saat fitur lain diperbaiki (*Regression Testing*).

## 🎯 Sprint Goal
Memastikan seluruh fitur aplikasi WARUNGku berjalan stabil, akurat, dan siap digunakan oleh pengguna nyata.

## 📦 Product Increment
- [x] Dokumen Skenario Test Case (Manual Testing).
- [x] Laporan Bug (Bug Report) dan status perbaikannya.
- [x] Perbaikan bug kritis (misal: kalkulasi harga salah, crash saat hapus).
- [x] Simulasi Berita Acara UAT.

## 💰 Nilai Bisnis
Reputasi adalah segalanya. Aplikasi yang stabil akan mendapatkan ulasan positif dan rekomendasi dari mulut ke mulut. Bagi developer, proses testing yang ketat mengurangi biaya *support* pasca-penjualan. Klien UMKM akan merasa investasi mereka sepadan jika aplikasi jarang bermasalah.

## ⏱ Alokasi Waktu (240 menit)
- **15 menit**: Standup - Review Notifikasi & Pengingat.
- **30 menit**: Teori: Jenis-jenis Testing & Pentingnya UAT.
- **150 menit**: Coding Sesi: Eksekusi Test Case & Bug Fixing.
- **30 menit**: Peer Testing: Siswa A mencoba "merusak" aplikasi Siswa B.
- **15 menit**: Sprint Review.

## 📋 Definition of Done
- [ ] Seluruh skenario test utama (Login, CRUD, POS, History) berstatus PASS.
- [ ] Tidak ada crash saat aplikasi digunakan secara intensif selama 10 menit.
- [ ] Angka kembalian dan total omzet 100% akurat.
- [ ] Daftar bug yang ditemukan telah diperbaiki dan diverifikasi ulang.
